## What already exists and must be reused, not rebuilt

- Pai Sho lives in `apps/pai-sho` (React 19, Three.js, Vite, TypeScript, Electron shell). The main menu (`src/ui/Menu.tsx`) already shows the four cards in the right order: Board and style (with the player's avatar among unlocked figurines), Campaign, Two on this device, Community. The Community card currently opens a full-screen section holding the old local profile card and the remote-play card (PeerJS, `src/reseau/pair.ts`, local friends in `paisho.amis`).
- The Salon monorepo ships a social kit in `packages/ui/src/reseau` (package `@inconnus/ui`, re-exported from the package root, `import { … } from '@inconnus/ui'`, as apps/salon does; add `"@inconnus/ui": "*"` to apps/pai-sho dependencies): `auth.ts` (loginWithGoogle, loginWithEmail, signUpWithEmail, ensureMember, subscribeToAuthState), `membres.ts` (MembreDoc, getMembre, suivreMembre, majMembre, listerMembres), `amities.ts` (friendships collection, docs keyed `uidA_uidB`, fields `uids`, `status` 'pending' | 'accepted'; demanderAmitie, accepterAmitie, retirerAmitie, suivreMesAmities), `dms.ts` (conversations collection, `members` array, `messages` subcollection with `uid`; ouvrirConversation), `notifications.ts` (notifications/{uid}/items, suivreMessagesNonLus, marquerConversationLue), `moderation.ts` (blocages, signalements), plus the components Avatar, ListeAmis, MonProfilForm, ProfilSocial, PageMembre, Cloche, MurSocial. This is the same social layer that was built for Krystine's site and then ported to the Creator Studio.
- The Firebase project is the Salon's (`le-salon-des-inconnus`), configured through `VITE_FIREBASE_*` variables in `apps/salon/.env.local` (copy them into `apps/pai-sho/.env.local`, never commit). `firestore.rules` at the monorepo root already covers `members`, `friendships`, `conversations` and `messages`, `notifications`, `blocages`, `signalements`. New collections for Pai Sho need rules added there and deployed with `npx firebase deploy --only firestore:rules`.
- The web build is served from `https://www.lesalondesinconnus.com/jeux/pai-sho/`, same origin as the Salon site, so a member signed in on the site is signed in in the game (same Firebase app, same IndexedDB persistence). The Electron build runs from `file://`, so it needs its own sign-in (email and password work everywhere; Google through `signInWithPopup` must be tested in Electron, with email as the fallback).
- Avatars: the player's avatar is one of the figurines they have unlocked (`paisho.progression`, ids in `src/jeu/adversaires.ts`, thumbnails `public/models/convives/vignettes/<id>.webp` or the equivalent, check `src/ui/Skins.tsx`). The banner is one of the game's boards or scenes, or an uploaded image through `images.ts` if the kit already handles uploads.

## Design canon

Dark warm glass, gold accents, 15 px rounded corners, no italics, titles never beyond two lines, Cinzel for accented display text (a watcher in `src/main.tsx` already swaps the display font for accented titles). Everything in French and English through `src/ui/textes.ts`. Every screen verified at 1440 and 390 with the `boucle-verdict` loop before it is called done.

## Features, in delivery order

1. Account. Sign in and sign up inside the Community section (Google and email), through the `@inconnus/ui` auth helpers and `ensureMember`. The username chosen at the first visit (dialog « Choisissez votre nom ») becomes the account's display name at sign-up; after sign-up, the account's display name replaces the local name everywhere (menu, VS splash, remote play `bonjour` message). Signed out, the Community section shows the sign-in card and keeps the remote-play card working as today with the local name.
2. Profile. A profile card with banner, avatar (chosen among unlocked figurines), display name, a short bio, campaign progress (opponents beaten), wins and losses online. Stored on `members/{uid}` for the shared fields (displayName, bio, photoURL) and on `members/{uid}/paisho/profil` for the game's fields (avatar id, banner id, record), with rules added for that subcollection (owner writes, signed-in members read).
3. Friends. Friend list, friend requests (send, accept, refuse, remove) through `amities.ts`, member search by display name through `listerMembres`, online presence through a `presence/{uid}` document (lastSeen heartbeat every 30 s while the game is open, read by friends). Replace the local `paisho.amis` carnet with the account's friend list when signed in; keep the local carnet only when signed out.
4. Chat. One-to-one chat through `dms.ts` conversations, unread badge through `suivreMessagesNonLus`, and group chat rooms: a `salons/{salonId}` collection (name, owner uid, `members` array, createdAt) with a `messages` subcollection, created from the Community section ("Create a group"), invite friends, leave. Rules mirror the conversations rules (members read and write, author on each message).
5. Challenges. "Challenge a friend" sends a `defis/{defiId}` document (from uid, to uid, status 'pending' | 'accepted' | 'declined' | 'expired', createdAt, peerId of the challenger) and a notification; accepting opens the PeerJS link exactly as "Join a table" does today with the challenger's peer id. A challenge expires after two minutes without an answer.
6. Matchmaking. "Challenge a random stranger" writes a `file-attente/{uid}` document (peerId, createdAt, rating optional); a client that finds another waiting document older than its own pairs with it (transaction: delete both, create a `defis` document accepted on both sides) and both open the PeerJS link. Timeout after 90 s with a clear message. Keep the TURN limitation visible: if the connection does not open within 20 s, say so and offer to retry; no TURN server exists yet (metered.ca account still to be opened by Alex).
7. Open a room. "Open a room" keeps today's host flow (PeerJS id shown, copy link) and, when signed in, also publishes the room in `salles-ouvertes/{uid}` (peerId, host name, createdAt) so friends see "X has an open table" with a Join button in the Community section. Remove the entry when the game starts or the host leaves.
8. Main menu. The "Your profile" square is gone (already done); the Community card shows, when signed in, the avatar, the display name, the number of friends online and the unread count; when signed out, "Sign in to find friends".
9. Moderation and safety. Block and report through `moderation.ts`; a blocked member cannot challenge, message or see presence. Messages capped at 2 000 characters, display names 2 to 24 characters, rate limits by rules where possible.
10. Electron. The same screens work in the Mac build: email sign-in confirmed, Google sign-in tested, and if popups fail in Electron, hide the Google button there (`window.paisho?.electron` or the existing detection).
